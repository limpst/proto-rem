# 03. 7단계 파이프라인 (Human-in-the-Loop)

## 전체 흐름

```
STEP 1  명함 수집      리멤버 반출 / CSV            [자동]
STEP 2  회사 식별      회사명 정규화 + 홈페이지 확정  [자동]
STEP 3  홈페이지 리서치 source·target 양쪽 크롤 → 근거 추출  [자동]
STEP 4  고객군 선택    세그먼트 자동분류 → 발송대상 확정  ★ HUMAN
STEP 5  카피 생성      세그먼트 프롬프트로 1:1 문안      [자동]
STEP 6  검토·승인      문안 수정 후 승인/반려          ★ HUMAN
STEP 7  발송·추적      승인 건만 발송, 이력·응답 기록    [자동]
```

사람이 개입하는 지점은 **정확히 두 곳**이다. 그 외 단계에 사람을 넣으면 처리량이 죽고, 이 두 곳에서 빼면 사고가 난다.

| 게이트 | 왜 사람이 필요한가 |
|---|---|
| **STEP 4 (대상 확정)** | 세그먼트 자동분류는 키워드 기반이라 오분류가 있고, 무엇보다 *이 사람에게 지금 연락하는 것이 관계상 적절한가*는 영업사원만 안다 |
| **STEP 6 (문안 승인)** | 생성된 문장이 사실이어도 톤·타이밍이 틀릴 수 있다. 발신자 이름으로 나가는 글은 발신자가 읽고 보내야 한다 |

## 단계별 상세

### STEP 1 — 명함 수집

세 가지 경로를 모두 지원한다. 상황에 맞는 것을 쓰면 된다.

| 방법 | 사용자 부담 | 반복 사용 | 언제 쓰나 |
|---|---|---|---|
| **① 전용 브라우저 로그인** | 최초 1회 로그인 | 버튼 하나 | 반복 수집. 평소 Chrome을 건드리지 않는다 |
| **② 콘솔 스니펫** | 붙여넣기 + 스크롤 | 매번 반복 | 지금 당장 한 번. 재시작·확장 불필요 |
| **③ CDP 접속** | Chrome 종료 후 재실행 | 버튼 하나 | 완전 자동화가 필요할 때 |

- ①은 `.auth/rem-profile` 전용 프로필을 쓴다. 구글 로그인이 차단되면 네이버·카카오를 쓴다.
- ②는 `public/collect-snippet.js` — fetch/XHR을 가로채 명함 API 응답을 모아 `cards.json`으로 내려받는다.
- ③은 `--remote-debugging-port=9222` 로 켠 Chrome에 붙는다.
- 산출은 셋 다 동일: `{id, name, title, company, dept, email, phone, site, met_at, note}`

> **로그인에 대한 설계 결정**: 구글·네이버는 Playwright가 띄운 브라우저의 로그인을 차단한다(`accounts.google.com/v3/signin/rejected`로 확인됨). 따라서 **자동 로그인을 시도하지 않고**, 사용자가 이미 로그인해 둔 Chrome에 CDP로 붙는다. 비밀번호가 시스템을 통과하지 않는다는 점에서 보안상으로도 이쪽이 낫다.

### STEP 2 — 회사 식별
회사명 정규화(㈜·(주)·공백 제거), 홈페이지 URL 확정. 명함에 URL이 없으면 검색 기반 후보 제시 → STEP 4에서 사람이 확인.

### STEP 3 — 홈페이지 리서치 (source + target 양방향)
- **target**: 상대 회사 홈페이지 → 건물 유형·규모·준공연도·시설 현황
- **source**: 자사(에이톰) 홈페이지 → 서비스 목록·공신력 근거·레퍼런스 프로젝트
- source를 하드코딩하지 않고 매번 읽는 이유: 홈페이지가 개편돼도 문안이 낡지 않고, **실제로 홈페이지에 적힌 역량만** 인용하게 강제되기 때문
- 산출: `signals.facts[]` — 이게 0개면 STEP 5에서 생성이 자동 차단된다

### STEP 4 — 고객군 선택 ★ HUMAN
7개 세그먼트로 자동 분류(`src/domain.mjs`) 후, 대시보드에서 세그먼트 단위 일괄 선택 + 개별 체크. 선택된 명함만 다음 단계로 간다.

### STEP 5 — 카피 생성
프롬프트 = 세그먼트 트리거 + 통증 + 인용 가능 실적(화이트리스트) + target 홈페이지 근거 + 채널 제약.
컴플라이언스 요소((광고) 표기·수신거부·서명)는 **LLM에 맡기지 않고 코드가 강제 삽입**한다.

### STEP 6 — 검토·승인 ★ HUMAN
자동 검증 6항목 결과를 배지로 표시하고, 제목·본문을 직접 편집 후 승인/반려. 승인된 건만 STEP 7로 간다.

### STEP 7 — 발송·추적
현재 프로토타입은 큐 적재까지만 수행한다. 실제 발송 연동 시 수신동의 확인 · 야간(21~08시) 차단 · 30일 내 중복 차단이 함께 적용된다.

## 상태 전이

```
NEW → RESOLVED → ENRICHED → SCORED → DRAFTED → APPROVED → QUEUED → SENT → REPLIED
                                       ↘ HELD (근거 부족)
                                       ↘ REJECTED (사람이 반려)
```
