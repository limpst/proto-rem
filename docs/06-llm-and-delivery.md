# 06. LLM 백엔드와 발송

## 1. LLM 백엔드

명함은 개인정보이므로 로컬 처리가 원칙적으로 낫다. 다만 **하드웨어가 그걸 허용하는지 먼저 재야 한다.**

### 실측 결과 (현 개발 PC: Snapdragon ARM64 + Adreno 680)

| 백엔드 | 모델 | 문안 1건 생성 | 비고 |
|---|---|---|---|
| ollama | exaone3.5:7.8b | **300초 초과** | GPU 가속 불가 (`/api/ps` 기준 VRAM 0GB, 전량 CPU) |
| ollama | exaone3.5:2.4b | **338초** | 크기를 1/3로 줄여도 개선 없음 |
| **claude-cli** | claude-sonnet-5 | **90초** | API 키 불필요. **현재 기본값** |

Ollama 는 Windows ARM64 에서 Adreno GPU 가속을 지원하지 않는다. 결론:
**이 PC에서 로컬 모델은 실용성이 없어 기본을 `claude-cli` 로 둔다.**
로컬 처리가 반드시 필요한 환경(예: NVIDIA GPU가 있는 서버)에서는 `LLM_BACKEND=ollama` 로 바꾸면 그대로 동작한다.

### 우선순위

`LLM_BACKEND` 를 지정하지 않으면 아래 순서로 자동 감지한다.

| 순위 | 백엔드 | 조건 | 특성 |
|---|---|---|---|
| 1 | ollama | `localhost:11434` 응답 | 로컬 실행, 데이터 유출 없음. **GPU 없으면 매우 느림** |
| 2 | claude-api | `ANTHROPIC_API_KEY` 존재 | 품질 최상, 토큰 과금. 배포 환경용 |
| 3 | claude-cli | Claude Code 설치됨 | 키 발급 불필요. 로컬 개발 기본값 |

`LLM_BACKEND=ollama|claude-api|claude-cli` 로 강제 지정할 수 있다.
모델은 `OLLAMA_MODEL` (기본 `exaone3.5:7.8b` — 한국어 비즈니스 문어체에 강함).

```powershell
winget install --id Ollama.Ollama -e
ollama pull exaone3.5:7.8b
```

> **품질 트레이드오프**: 로컬 7.8B 모델은 Claude 대비 JSON 형식 준수율과 문장 밀도가 떨어진다.
> 이를 보완하는 것이 `validate()` 검증 6~7항목과 `applyCompliance()` 강제 삽입이다.
> **모델 품질에 기대지 않고 코드로 하한선을 만드는 것**이 이 설계의 핵심이다.

## 2. 발신자 명의 (Persona)

같은 근거라도 누구 이름으로 나가느냐에 따라 톤이 달라야 한다. STEP 2에서 선택한다.

| 명의 | 톤 | 약속할 수 있는 범위 |
|---|---|---|
| **대표** | 짧고 단정하게. 결정권자 대 결정권자 | "직접 검토해 드리겠습니다" |
| **마케팅 담당자** | 실무적·친절. 무상 제공물과 수령 절차를 명확히 | 자료 제공, 일정 조율 |
| **영업 담당자** | 만난 맥락을 먼저 짚고 한 가지만 제안 | 현장 방문, 사전 검토 |
| **기술 담당자** | 기술 근거 우선. 전문용어는 1~2개로 제한 | 점검 방법·소요 일정 설명 |

## 3. 1:1 과 1:N

STEP 2에서 선택하며, STEP 5의 생성 방식이 갈린다.

| | 1:1 개별 맞춤 | 1:N 고객군 공통 |
|---|---|---|
| 생성 단위 | 명함 1건 = 문안 1건 | 고객군 1개 = 문안 1건 |
| 근거 | 그 회사 홈페이지에서 뽑은 사실 | 고객군 공통 트리거 |
| 개인화 | 깊음 (회사 고유 사실 인용) | 얕음 (이름·회사만 치환) |
| 모델 호출 | 대상 수만큼 | 고객군 수만큼 |
| 추가 검증 | — | C9 병합필드 잔여 없음 |
| 쓸 곳 | 고가치 대상, 재접촉 | 대량 초기 접촉 |

1:N 문안의 병합필드는 `{{name}}` `{{title}}` `{{company}}` 세 개로 제한한다. 늘리면 치환 실패가 그대로 발송된다.

## 4. 프롬프트 가시화

프롬프트가 곧 제품 로직이므로 대시보드에서 원문을 그대로 볼 수 있다.

- **STEP 3** — "이 설정으로 만들어지는 프롬프트 보기": 현재 명의·모드·리서치 근거로 조립된 프롬프트 전문
- **STEP 5/6** — 각 문안의 "이 문안을 만든 프롬프트": 실제로 사용된 프롬프트 (사후 감사용)

고칠 곳은 `src/domain.mjs`(고객군 정의: 트리거·통증·실적)와 `src/generate.mjs`(작성 규칙·출력 형식)다.

## 5. Gmail 발송

`.env` (커밋 금지, `.gitignore` 포함):

```
GMAIL_USER=보내는주소@gmail.com
GMAIL_APP_PASSWORD=앱비밀번호16자리
GMAIL_FROM_NAME=에이톰엔지니어링
DRY_RUN=1                      # 1이면 실제 전송 대신 성공만 반환
```

앱 비밀번호는 **Google 계정 > 보안 > 2단계 인증 > 앱 비밀번호**에서 사용자가 직접 발급한다.
계정 비밀번호는 쓸 수 없고, 써서도 안 된다.

### 발송 안전장치

| 장치 | 동작 |
|---|---|
| 승인 게이트 | `reviewStatus === 'APPROVED'` 인 건만 전송 |
| 기본 dry-run | 버튼 기본값은 큐 적재. 실제 전송은 별도 버튼 + 확인 대화상자 |
| 야간 차단 | 21~08시에는 전송 거부 (정보통신망법상 야간 광고 전송 제한) |
| 미설정 차단 | `.env` 없으면 실제 발송 버튼 자체가 비활성 |
