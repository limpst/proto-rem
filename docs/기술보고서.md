# SafeLead 기술보고서 — 아주 쉽게 쓴 설명서

> 이 글은 **컴퓨터를 하나도 모르는 사람**도 읽을 수 있게 썼습니다.
> 어려운 말이 나오면 바로 옆에 쉬운 말로 다시 적어 두었습니다.
> 천천히, 앞에서부터 읽으시면 됩니다.

작성일: 2026년 8월 30일 · 대상: ㈜에이톰엔지니어링

---

## 1. 이 프로그램은 무엇인가요?

### 한 줄로 말하면

**"명함을 넣으면, 보낼 만한 편지를 만들어 주는 기계"** 입니다.

### 조금 더 자세히

회사에는 명함이 아주 많이 쌓여 있습니다. 서랍에 넣어 두면 그냥 종이일 뿐입니다.
그 명함으로 편지를 보내고 싶은데, 문제가 있습니다.

- 명함이 3,000장이면, 편지도 3,000통을 써야 합니다. 사람이 다 못 씁니다.
- 그렇다고 똑같은 편지를 3,000명에게 보내면, 아무도 읽지 않습니다.

그래서 이 기계를 만들었습니다.

```
   [명함]  →  ( 기계 )  →  [그 회사에만 맞는 편지]
   3,000장                    3,000통
```

### 왜 "그 회사에만 맞는" 편지여야 하나요?

편지를 두 개 비교해 봅시다.

**나쁜 편지**

> 안녕하세요. 저희는 안전진단 전문업체입니다. 잘 부탁드립니다.

읽는 사람 생각: *"그래서 나한테 왜 보냈지?"* → 바로 지웁니다.

**좋은 편지**

> 안녕하세요. 귀사 홈페이지에서 1998년에 지은 8층 건물을 보았습니다.
> 지하주차장이 3개 층이더군요. 이런 건물은 법으로 정해진 점검 시기가
> 다가오는 경우가 많습니다. 한번 확인해 보시겠어요?

읽는 사람 생각: *"어? 우리 건물 얘기네."* → 읽습니다.

**이 기계는 두 번째 편지를 씁니다.** 그러려면 그 회사를 먼저 **알아야** 합니다.
그래서 이 기계는 편지를 쓰기 전에 **그 회사 홈페이지를 직접 읽습니다.**

## 2. 기계 안에서 무슨 일이 일어나나요? — 7개의 방

이 기계는 방이 7개인 공장 같습니다. 명함이 1번 방에서 들어와서 7번 방으로 나갑니다.

```
 1번방      2번방      3번방      4번방      5번방      6번방      7번방
 명함       누구       홈페이지    누구에게    편지       사람이     보내기
 모으기  →  이름으로 →  읽기    →  보낼지  →  쓰기    →  읽어보고 →
            보낼지                고르기               승인하기
```

### 1번 방 · 명함 모으기

리멤버(명함 앱)에서 명함을 가져옵니다. 가져오는 방법이 세 가지 있습니다.

| 방법 | 어떻게 | 언제 쓰나 |
|---|---|---|
| ① 전용 브라우저 | 이 프로그램만 쓰는 크롬 창을 열어 한 번 로그인 | 명함이 많을 때 |
| ② 콘솔 붙여넣기 | 리멤버 화면에서 작은 주문 하나를 붙여넣기 | 크롬을 껐다 켜기 싫을 때 |
| ③ 그냥 타이핑 | 명함 내용을 상자에 붙여넣기 | 몇 장 안 될 때 |

**중요한 약속:** 이 프로그램은 **비밀번호를 받지 않습니다.**
로그인은 사람이 직접 하고, 프로그램은 그 결과만 빌려 씁니다.

### 2번 방 · 누구 이름으로 보낼지 정하기 `사람이 결정`

- **누가 보내는 걸로 할까요?** 대표님 / 마케팅 / 영업 / 기술 — 고르는 사람에 따라 말투가 달라집니다.
- **한 명씩 따로 쓸까요, 여럿에게 같은 걸 보낼까요?**
  - 1:1 = 한 사람당 한 통. 답장이 잘 오지만 오래 걸립니다.
  - 1:N = 같은 종류끼리 한 통. 빠르지만 내용이 두루뭉술합니다.
- 여기서 각 회사의 **홈페이지 주소**도 찾습니다.

홈페이지 주소를 찾는 순서:

```
① 명함에 적혀 있나?  →  있으면 그걸 쓴다
② 없으면 이메일을 본다.  hong@atom-eng.co.kr  →  atom-eng.co.kr 일까?
③ 그래도 없으면 AI 에게 물어본다. "에이톰엔지니어링 홈페이지가 뭘까?"
④ 어느 경우든 실제로 접속해 본다. 진짜 열리는 주소만 쓴다.
```

### 3번 방 · 홈페이지 읽기

찾은 홈페이지에 진짜로 들어가서 글을 읽습니다. 그리고 **편지에 쓸 만한 사실**을 뽑아냅니다.

예를 들면 이런 것들입니다.

- "국토교통부가 지정한 안전진단 전문기관이다"
- "30년 동안 일했다"
- "드론으로 철탑을 점검한 적이 있다"

이걸 **근거**라고 부릅니다. 근거가 없으면 **편지를 만들지 않습니다.**
지어내서 쓰면 거짓말이 되기 때문입니다.

### 4번 방 · 누구에게 보낼지 고르기 `사람이 결정`

회사를 8가지 종류로 나눕니다. 이걸 **고객군**이라고 부릅니다.

| 고객군 | 어떤 회사인가 | 이 회사의 걱정거리 |
|---|---|---|
| 리테일 · 복합몰 | 백화점, 마트, 쇼핑몰 | 장사를 멈추지 않고 점검해야 함 |
| 대학 · 병원 캠퍼스 | 대학교, 병원 | 건물이 여러 동이라 점검 시기가 제각각 |
| 오피스 · 자산관리 | 빌딩을 사고파는 회사 | 팔 때 안전 서류를 급히 찾음 |
| 방송 · 통신 | 철탑, 중계소 | 사람이 높이 올라가야 해서 위험함 |
| 시공사 · 정비사업 | 건설회사, 재건축조합 | 건물을 부술 때 옆 건물이 걱정 |
| 제조 · 물류 | 공장, 창고 | 공장을 멈추지 않고 점검해야 함 |
| 건축물 안전진단 | 같은 일을 하는 회사 | 큰 일을 같이 할 짝을 찾음 |
| 공공 · 시설관리공단 | 시청, 공단 | 반년마다 정해진 점검을 해야 함 |

나누는 방법은 두 가지입니다.

1. **규칙으로 나누기** — 회사 이름에 "백화점"이 들어가면 리테일. 빠르고 공짜입니다.
2. **AI 에게 물어보기** — 규칙으로 모르겠는 것만 AI 가 봅니다. 느리지만 똑똑합니다.

그다음 **사람이** 보낼 사람을 고릅니다. 왜 사람이 고르냐면,
*"지금 이 사람한테 연락해도 되는 사이인가?"* 는 담당자만 알기 때문입니다.

### 5번 방 · 편지 쓰기

AI 에게 이렇게 부탁합니다(이 부탁하는 글을 **지시문**이라고 합니다).

> 너는 에이톰엔지니어링의 영업 담당이야.
> 받는 사람: 한빛유통 김성호 시설관리팀장
> 이 회사 홈페이지에서 알아낸 사실: (3번 방에서 뽑은 근거)
> 우리 회사 실적: (에이톰 홈페이지에서 뽑은 것)
> 규칙: 거짓말하지 마라. 법에 걸린다고 단정하지 마라. 첫 편지에 돈 얘기 하지 마라.

AI 가 편지를 씁니다. 한 통에 10초~3분 걸립니다(어떤 AI 를 쓰느냐에 따라).

### 6번 방 · 사람이 읽어보고 승인하기 `사람이 결정`

만들어진 편지를 **사람이 반드시 읽습니다.** 고칠 수도 있습니다.

기계가 먼저 6가지를 스스로 검사합니다.

- ✓ 홈페이지에서 본 사실을 인용했는가
- ✓ 우리 실적을 인용했는가
- ✓ "법에 걸립니다" 라고 단정하지 않았는가
- ✓ (광고) 표시를 했는가
- ✓ 수신거부 안내를 넣었는가
- ✓ 첫 편지에 견적을 요구하지 않았는가

그래도 **마지막 결정은 사람**입니다. 승인한 것만 다음 방으로 갑니다.

### 7번 방 · 보내기

승인한 편지만 나갑니다. 나가기 전에 안전장치가 걸립니다.

- 밤 9시부터 아침 8시까지는 **안 나갑니다** (법으로 정해져 있습니다)
- 승인하지 않은 것은 **안 나갑니다**
- **우리 회사 사람에게는 안 나갑니다** (광고를 우리끼리 보낼 이유가 없습니다)
- 이메일 주소가 없으면 **안 나갑니다**
- 연습 모드면 보내는 척만 하고 **안 나갑니다**

## 3. 무엇으로 만들었나요?

### 재료

| 부분 | 무엇을 썼나 | 왜 |
|---|---|---|
| 서버(본체) | Python (파이썬) | 파이썬에 원래 들어 있는 것만 씁니다. 설치할 게 없습니다 |
| 화면 | HTML + JavaScript | 따로 도구를 쓰지 않았습니다. 파일 두 개면 됩니다 |
| 저장 | SQLite | 파일 하나가 데이터베이스입니다. 옮기기 쉽습니다 |
| 명함 수집 | Playwright | 사람 대신 브라우저를 눌러 주는 도구 |
| AI | Claude 또는 Ollama | 편지를 쓰는 부분 |

### 왜 이렇게 단순하게 만들었나요?

부품이 많으면 고장 날 곳도 많습니다.
이 프로그램은 **한 사람이 한 컴퓨터에서 켜고 끌 수 있어야** 합니다.
그래서 설치할 것을 최대한 줄였습니다.

### 폴더가 어떻게 생겼나요?

```
proto-rem/
├── py/              ← 서버 (파이썬). 여기가 본체입니다
│   ├── server.py    ← 모든 요청을 받는 곳
│   ├── store.py     ← 저장하고 꺼내는 곳
│   ├── domain.py    ← 고객군 8가지 정의
│   ├── enrich.py    ← 홈페이지 읽는 곳
│   ├── generate.py  ← 편지 쓰는 곳
│   └── deliver.py   ← 메일 보내는 곳
├── public/          ← 화면
│   ├── index.html   ← 뼈대
│   ├── app.js       ← 움직이는 부분
│   └── login.html   ← 로그인 화면
├── scripts/         ← 명함 수집 (Node.js)
└── data/            ← 데이터가 쌓이는 곳
```

## 4. 꼭 알아야 할 안전장치

### 왜 안전장치가 필요한가요?

명함은 **개인정보**입니다. 남의 이름·전화번호·이메일입니다.
그리고 광고 메일은 **법으로 규칙이 정해져 있습니다**(정보통신망법).
잘못하면 회사가 곤란해집니다.

### 어떤 장치가 있나요?

**① 로그인**

프로그램을 회사 서버에 올리면, 주소를 아는 사람은 누구나 열 수 있습니다.
명함이 전부 보입니다. 그래서 비밀번호를 걸 수 있게 했습니다.

```
비밀번호를 정해 두면  →  화면이 잠긴다  →  아는 사람만 들어온다
비밀번호를 비워 두면  →  아무나 들어온다  →  내 컴퓨터에서 혼자 쓸 때만!
```

**② 비밀값은 내 컴퓨터에서만 보입니다**

API 키나 메일 비밀번호 같은 것은 ⚙ 설정 화면에서 볼 수 있는데,
**내 컴퓨터에서 열었을 때만** 보여 줍니다. 인터넷 주소로 열면 거부합니다.

**③ 테스트할 때는 내 주소로만**

연습할 때 진짜 고객에게 메일이 가면 큰일입니다.
그래서 **"모든 메일을 내 주소로만 보내기"** 를 켤 수 있습니다.
원래 받을 사람 이름은 제목에 남겨 두어, 무엇이 누구에게 갈 편지였는지 알 수 있습니다.

```
켜기 전:  김성호님 → sh.kim@hanbit.co.kr   (진짜 고객)
켜고 나서: 김성호님 → 내 주소               (제목: [테스트→sh.kim@hanbit.co.kr] ...)
```

**④ 우리 회사에는 안 보냅니다**

명함 중에 우리 회사 사람이 섞여 있을 수 있습니다.
그 사람들은 **자사** 로 표시되고, 어떤 방법으로도 메일이 나가지 않습니다.

## 5. 이번에 무엇을 고쳤나요?

프로그램을 처음부터 끝까지 눌러 보면서 찾은 문제들입니다.

### 고친 것 (심각한 순서)

| # | 무슨 문제였나 | 왜 생겼나 | 어떻게 고쳤나 |
|---|---|---|---|
| 1 | **버튼 하나만 눌러도 화면이 죽었다** | 서버가 화면에 필요한 정보를 일부만 돌려줬다 | 돌려주는 곳을 한 군데로 모아, 빠뜨릴 수 없게 만들었다 |
| 2 | **한 번 죽으면 새로고침 전까지 아무 버튼도 안 들었다** | "작업 중" 표시를 끄는 코드가 실행되지 않았다 | 무슨 일이 있어도 반드시 끄도록 바꿨다 |
| 3 | **[메일 만들기]가 항상 실패했다** | 화면을 다시 그리면서 입력칸을 지워 버렸다 | 값을 화면 밖에 따로 보관하도록 바꿨다 |
| 4 | **[붙여넣기]도 같은 이유로 항상 실패했다** | 위와 같음 | 위와 같음 |
| 5 | **우리 회사에 광고 메일이 나갈 뻔했다** | 예전에 만든 편지가 남아 있으면 승인 상태만으로 발송됐다 | 자사·제외는 어떤 경우에도 막았다 |
| 6 | **실제 발송이 "Failed to fetch" 로 끊겼다** | 메일 한 통에 30초가 걸려 연결이 먼저 끊겼다 | 오래 걸리는 일은 따로 돌리고 진행률만 보여준다 |
| 7 | **홈페이지 읽기가 무조건 실패했다** | `atom-eng.co.kr` 처럼 `https://` 가 없으면 못 읽었다 | 읽기 직전에 자동으로 붙여 준다 |
| 8 | **고쳐도 화면이 안 바뀌었다** | 브라우저가 옛 파일을 계속 쓰고 있었다 | 서버가 "바뀌었는지 매번 확인해라" 라고 알려주게 했다 |
| 9 | **설정을 바꿔도 안 먹혔다** | 호스팅 설정이 더 세서 무시됐는데 화면은 말이 없었다 | 못 바꾸는 항목은 잠그고 이유를 알려준다 |
| 10 | **비밀값이 누구에게나 보였다** | 인증 없이 볼 수 있었다 | 내 컴퓨터에서만 보이게 막았다 |
| 11 | **명함 파일을 올리면 홈페이지가 사라졌다** | 읽어들일 때 그 칸을 보지 않았다 | 보도록 고쳤다 |
| 12 | **로그 한 줄 때문에 요청이 죽었다** | 윈도우 화면이 못 찍는 글자가 있었다 | 로그가 실패해도 무시하고 넘어간다 |

### 새로 만든 것

- **로그인** — 비밀번호로 화면 전체를 잠급니다
- **명함 고치기** — 표에서 이름·회사·이메일을 바로 고칩니다
- **명함 순서 바꾸기** — [맨 위로] 로 중요한 사람을 위에 둡니다
- **큐 되돌리기** — 보내기 직전 목록에서 뺄 수 있습니다
- **한 건만 즉시 발송** — 전체가 아니라 한 통만 지금 보냅니다
- **수신 주소 바로 고치기** — 주소가 없어 막힌 건을 그 자리에서 고칩니다
- **테스트 수신 주소** — 모든 메일을 내 주소로만 보냅니다
- **버튼 설명(툴팁)** — 모든 버튼에 "누르면 무슨 일이 생기는지" 를 붙였습니다
- **데이터 영구 저장** — 서버를 다시 올려도 데이터가 남게 준비했습니다

## 6. 진짜로 해 봤습니다 (검증)

말로만 "됩니다" 라고 하면 믿기 어렵습니다. 실제로 돌려 본 결과입니다.

### 리멤버에서 진짜 명함 가져오기

```
로그인      전용 브라우저에 로그인 상태 확인
수집        리멤버가 보낸 데이터 24개를 가로채서 명함 3장 추출
결과        명함 3장 (이종하 / 호은성 / 본인 프로필)
```

**명함이 3장뿐인 이유:** 이 계정에 실제로 2장밖에 없습니다.
리멤버가 직접 알려줍니다 — `total_count: 2`. 기계가 놓친 게 아닙니다.

### 7개 방을 끝까지 통과시키기

```
1번방  명함 7장
2번방  홈페이지 5개 찾음
3번방  근거 5개 회사에서 확보
4번방  5장은 우리 회사(발송 안 함), 1장을 사람이 직접 골라 지정
5번방  편지 6통 완성
6번방  6통 승인
7번방  2통 실제 발송 성공 → 전부 테스트 주소로 도착
```

발송이 2통만 성공한 이유: 나머지 4장은 **명함에 이메일 주소가 없었습니다.**
그래서 "수신 주소 바로 고치기" 버튼을 만들었습니다.

### 자동 점검

```
전체 자동 점검(smoke)   통과 7 / 실패 0
화면 요소 597개          버튼 설명 빠진 것 0개
브라우저 오류            0건
고객군 버튼 10개         전부 정상 (각 9장씩 선택)
```

## 7. 아직 못 한 것 · 앞으로 할 것

솔직하게 적습니다.

| 무엇 | 지금 상태 | 하려면 |
|---|---|---|
| 인터넷 서버에서 AI 쓰기 | **안 됨** | Render 설정에 API 키를 넣고 `claude-api` 로 바꿔야 합니다 |
| 인터넷 서버에 데이터 영구 저장 | **안 됨** | 유료 플랜으로 올리고 디스크를 붙여야 합니다 (코드는 준비됨) |
| 인터넷에서 명함 수집 | **안 됨** | 서버에는 크롬이 없습니다. 사내 서버에서는 됩니다 |
| 고객 명단을 인터넷에서 많이 모으기 | **없음** | 아직 만들지 않았습니다 |
| 사용자별 계정 | **없음** | 지금은 비밀번호 하나를 같이 씁니다 |

### 다음에 하면 좋을 순서

1. **Render 설정 고치기** — API 키 넣기 (5분)
2. **사내 서버에 올리기** — 명함 수집까지 전부 되는 유일한 방법
3. **비밀번호 켜기** — 사내망이라도 반드시
4. **키 바꾸기** — 대화창에 그대로 적었던 키·비밀번호는 새로 발급받기
