### 고침 — 안전에 관한 것

| 증상 | 왜 위험한가 | 조치 |
|---|---|---|
| **자사(에이톰) 명함에 광고 메일이 나갈 뻔함** | 선택에서는 막았지만, 예전 실행의 문안이 남아 있으면 '승인됨' 만으로 발송 목록에 끼어듦. 실제 검증에서 5건이 대상에 포함됨 | 전체 발송·건별 발송 양쪽에서 자사·제외를 차단 |
| ⚙ 설정의 비밀값이 인증 없이 노출 | 배포 주소를 아는 누구나 API 키·앱 비밀번호 원문을 받아 갈 수 있었음 | 원문은 루프백(내 PC)에서만. 외부는 403 |
| **홈페이지를 읽고도 그 결과가 버려짐** | 대체 대입이 `except` 밖에 있어 성공 결과를 항상 덮어씀. `e` 가 없어 NameError 로 죽기도 함 | 대입을 `except` 안으로. 확인: chars 2618 · 실제 분석 유지 |
| 다른 회사 사실이 '이 회사에서 확인된 사실'로 인용됨 | 프롬프트가 근거 목록을 "수신자 홈페이지에서 확인된 사실" 로 제목 붙이고 인용을 강제함 → A사 실적이 B사 메일에 B사 것처럼 | 문장 자체에 출처를 박음: `같은 업종 사례(A사) — …` |

### 새로 — 기능

- **접속 로그인** — `APP_PASSWORD` 를 넣으면 화면·API 전체가 잠김. HttpOnly 쿠키 30일,
  서버에 세션 저장소 없음(재시작해도 유지, 비밀번호 변경 시 전원 로그아웃), 오답에 1초 지연
- **명함 CRUD** — 표에서 이름·직함·회사·이메일·전화를 바로 고침(`수정`/`저장`/`취소`),
  `삭제`, `맨 위로`(순서 저장됨)
- **발송 이력 관리** — `큐에서 빼기` / `큐 비우기` / 건별 `즉시 발송` /
  수신 주소 인라인 `수정`
- **테스트 수신 리디렉션** — `TEST_REDIRECT_TO` 를 넣으면 모든 메일이 그 주소로만.
  원래 수신자는 제목 `[테스트→주소]` 와 본문 머리에 남음
- **버튼 툴팁** — 화면의 모든 클릭 요소에 "누르면 무슨 일이 생기는가". 되돌릴 수 없는
  동작·오래 걸리는 동작·비활성 사유를 문구에 명시. 누락 0개
- **데이터 영구 저장 준비** — `py/paths.py` 가 읽기 전용 자산(seed)과 살아남아야 할
  상태(DB·`.env`·업로드본)를 분리. 영구 디스크가 있으면 자동으로 그쪽에 저장

### 바꿈 — 동작 방식

- **1~7단계 전 구간 fallback** — 어디서 막혀도 업종 표준값으로 채우고 다음 단계로.
  4단계 미분류는 기본 고객군(`DEFAULT_SEGMENT`, 기본 `office`)으로 대체.
  전부 `✧추정` 으로 표시되고 사람이 뒤집을 수 있음
- **같은 회사 중복 조회 제거** — 에이톰 명함 5장이면 홈페이지를 5번 찾고 5번 읽었음.
  회사명·URL 기준으로 1회만. 확인: 읽기 3회 / 서로 다른 주소 3개
- **홈페이지 분석 결과 영구 보관** — `py/site_store.py`. URL 정규화(스킴·www·끝슬래시)
  후 회사 단위 저장, TTL 30일, 실패 기록은 6시간
- **7단계 주소 없음** — `SEND_FAILED` 가 아니라 `NO_EMAIL`(건너뜀). 진짜 실패가 묻히지 않게
- **샘플 시드** — 12건 → 5건 → **72건**(고객군 8종 × 9건). 고객군 버튼이 전부 0 이면
  눌러도 아무 일이 없어 기능 확인이 안 됐음. 분류 불일치 0건

### 아직 안 되는 것

| 무엇 | 왜 | 필요한 조치 |
|---|---|---|
| 배포본에서 AI | `LLM_BACKEND=claude-cli` 인데 서버에 CLI 없음, API 키 없음 | Render Environment 에 `ANTHROPIC_API_KEY` 추가 + `claude-api` 로 변경 |
| 배포본 데이터 영구 저장 | 무료 플랜은 재배포마다 파일 시스템 초기화 | 유료 플랜 + `render.yaml` 의 `disk:` 주석 해제 (코드는 준비됨) |
| 배포본에서 명함 수집 | 서버에 크롬이 없음 | 사내 서버에 올리면 그대로 동작 |
